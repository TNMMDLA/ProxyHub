# ProxyHub V0.2 Architecture

## Boundary

V0.2 follows one invariant: **One Policy Model, Multiple Compiler Adapters**.

```text
Node -> Node Pool -> Policy -> ordered Policy Rule
     -> policy-core normalized model
     -> Mihomo | sing-box | Raw adapter
     -> Subscription -> secure token -> client
```

The server Xray runtime configuration remains separate. Node mutations still use `xray-manager` and the Agent validation/atomic rollback lifecycle. Policy compilation never calls the Agent and compile preview never changes Xray or Node data.

## Data model

- `Policy`: name, description, enabled, revision, default action, optional default Node Pool.
- `PolicyRule`: stable policy relation, enabled flag, numeric priority, match type/value, action, optional Node Pool.
- `Subscription`: Policy relation, fixed format, enabled flag, token hash/prefix, optional expiration, last access.

Rules never reference an individual Node. Node Pool membership is queried for each compile, so changes appear on the next subscription request without copying membership into Policy records.

The migration `20260723000100_v02_policy_subscription` only creates new tables and indexes. It does not reset, drop, or rewrite V0.1.1 data.

## Determinism

`policy-core` filters disabled rules/nodes, then sorts rules by priority and ID, nodes by name and ID, pools by name and ID, and pool members by priority and node ID. Equivalent input produces byte-identical output.

Conflict handling uses **First Match Wins**. Duplicate rules produce explicit warnings; they are never silently removed. Missing pools, invalid values, disabled policies, and referenced pools with no enabled nodes are compile errors.

## Responsibility split

- Web: interaction, rule ordering, validation hints, masked/full preview display.
- Server: authenticated CRUD, authorization, database integrity, audit, notification, token validation, public responses.
- policy-core: validation, normalization, capability checks, deterministic adapters.
- Agent: Xray runtime lifecycle only.
- xray-manager: server Xray Reality configuration only.
