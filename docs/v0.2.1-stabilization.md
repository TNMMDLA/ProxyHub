# ProxyHub V0.2.1 Stabilization

## Scope and release state

V0.2.1 hardens the existing Policy Studio and Subscription Engine. It does not add Rule Sets, remote rule providers, policy templates, traffic collection, quotas, billing, multi-user plans, remote Agent enrollment, or multi-server orchestration.

Release state: **Development / Pre-production**. **V0.1.1 Linux Production Smoke Test Pending** remains a blocking production gate. Passing local tests or GitHub Actions demonstrates repeatability, not real-VPS acceptance.

The architectural boundary is unchanged:

- `policy-core` compiles client subscription content only.
- `xray-manager` and Agent own server-side Xray runtime validation, atomic apply, restart, health checks, and rollback.
- A client compiler never writes `/etc/xray/config.json` or invokes the Agent.

## Compiler evidence

- Byte-for-byte Golden outputs are stored beside a fixed policy input for Mihomo YAML, sing-box JSON, and raw VLESS.
- Scenario tests cover node-pool routing, direct/reject actions, multiple nodes/pools, disabled and offline nodes, disabled rules, First Match Wins ordering, all default actions, empty/missing pools, unsupported rules with identity, and special characters.
- Every adapter compiles the same input 100 times and compares SHA-256 outputs.
- Rule capability tests exercise every match type against every adapter.
- Boundary tests include malformed domains, whitespace, empty values, IPv4 `/33`, IPv6 `/129`, invalid addresses, port limits/ranges, invalid networks, geo values, and length limits.
- YAML and JSON outputs are parsed after injection-style special-character inputs; VLESS query and fragment encoding has dedicated tests.

Adapter metadata is explicit and private to the compile result: adapter name, adapter version, validation target, routing support, and supported rule types. Diagnostics always contain code, severity, adapter, and message, plus rule ID/name/type when applicable.

## Real client-core validation

`scripts/compat/versions.env` is the single source of fixed versions, official release asset names, and SHA-256 checksums. The Windows and Linux scripts download only those assets, verify the checksum before extraction, generate configs from the Golden input, then call the official CLIs:

```text
Mihomo v1.19.28: mihomo -t -f <config> -d <isolated-home>
sing-box 1.13.12: sing-box check -c <config>
```

The local Windows run passed both cores. Linux execution is enforced by GitHub Actions and must also be repeated on the deployment VPS. CLI validation does not claim compatibility with Clash Verge Rev, Mihomo Party, sing-box GUI wrappers, or platform-specific import/share features.

## Migration evidence

Migration integration tests create two isolated databases:

1. an empty SQLite file followed by every real Prisma migration;
2. a V0.1.1 schema populated with administrator, session, server, node, private-key ciphertext, pool, and membership sentinels, baselined at the foundation migration and upgraded with the additive V0.2 migration.

Tests verify sentinel preservation, new table availability, Prisma migration history, `PRAGMA foreign_key_check`, subscription-protected Policy deletion, and policy-protected Node Pool deletion. No migration reset or destructive rewrite is used.

## Subscription security decisions

- Tokens contain 32 random bytes (256 bits); SQLite stores only a 64-character SHA-256 hash and an eight-character administration prefix.
- Create/rotation returns plaintext once. List, detail, audit, notification, and normal logs never return the hash or plaintext.
- Rotation replaces the database hash atomically. A concurrent in-flight old request may finish before the update, but after the update commits the old URL deterministically returns the same `404` as an unknown token.
- Public compiler errors are sanitized; authenticated previews retain actionable diagnostics.
- Request logging redacts `/sub/<token>` before serialization. Recursive metadata redaction covers password, token, TOTP, secret, recovery-code, and private-key key families.
- The public route returns a normalized `429 RATE_LIMITED` after 30 requests per effective client IP per minute.
- Content-derived ETags are stable across `lastAccessAt` changes and change when subscription content changes.
- `Cache-Control: private, no-store` prevents credential-bearing subscription bodies from being retained by caches.

## Continuous integration

`.github/workflows/ci.yml` runs on pushes to `master` and pull requests. It uses a frozen pnpm lockfile and has independent gates for:

- typecheck, lint, format check, unit/integration tests, and build;
- fresh and populated V0.1.1 upgrade migrations;
- checksum-pinned official Mihomo and sing-box validation;
- Compose configuration, Caddy image pull, and builds of Web, Server, Agent, and Xray images.

The workflow contains no deployment, SSH, production credentials, or server mutation steps.
